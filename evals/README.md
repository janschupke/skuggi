# skuggi evals

A committed, **local-only**, framework-free evaluation system for the agent.
There is no eval SDK and nothing is ever uploaded: the judge is skuggi's own
provider-agnostic chat model, and the baseline lives in git, not in a cloud
project.

## Two tiers

| Tier | Dimensions | Oracle | Runs |
|------|-----------|--------|------|
| **deterministic** | `compliance`, `methodology`, `schema`, `result_compat` | skuggi's own pure functions (`check_command`, `clamp_phase`, the protocol schemas, the ledger + report) | default test suite + `skuggi-eval --tier det`; **hard-gates CI** |
| **quality** | `factuality`, `budget`, `latency` | an in-house `LLMJudge` (`skuggi.eval.judge`), token cost, wall-clock | `skuggi-eval` / `make bench`; needs a provider; **never blocks CI** |

The deterministic tier is scored offline against pure oracles, so it runs inside
the default suite's `filterwarnings = ["error"]`. The quality tier needs a live
model and is opt-in.

## Configurable model matrix + divergence

The quality tier runs against a **matrix** of models, defined in `models.json`
(`matrix`, plus a pinned `judge` and a `fast` subset) and overridable per run with
`--provider`/`--model`. Running the same cases on several models surfaces
**divergence**: `skuggi.eval.divergence` flags a regression when the per-dimension
score spread across models exceeds that dimension's `divergence_tolerance`, or
when the models disagree on crossing the threshold (one passes, another fails).

The LLM judge splits into two suites (`--suite`):

- `fast` — a curated, cheap case subset graded by a single model, for a quick signal.
- `full` — every case across the whole matrix (the default; what `make bench` runs).

A quality case opts into `fast` with `"suites": ["fast", "full"]`; the default is
`["full"]`.

## Layout

- `models.json` — the quality-tier model matrix, the judge, and the `fast` subset.
- `scopes.json` — reusable engagement scopes referenced by `scope_ref`.
- `goldens/<dimension>.json` — the curated cases (`{dimension, description, cases}`).
- `baseline.json` — per-dimension `{score, threshold, provider}` (+ `divergence_tolerance`
  and per-model `models` for the quality tier); the gate floor. A `null` score
  means "not yet baselined" — gated on `threshold` alone.
- `prices.json` — the token price table loaded into each eval `Settings.model_prices`
  so the budget dimension prices whatever models the matrix configures.
- `scorecard.md` — regenerated by `make bench` (per-dimension, the model matrix, and
  the divergence verdict vs baseline).

## Scope boundary

Automated evals use **only synthetic documentation ranges** — RFC 5737 TEST-NET
(`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`) and RFC 3849 IPv6
(`2001:db8::/32`) — plus the frozen e2e fixture catalogued in `docs/lab.md`. The
`labs/` **practice range** (its networks, hosts and planted loot) is deliberately
**out of scope**: no golden or scope here references a practice-lab network, and
evals stand up **no lab**. The deterministic and `result_compat` dimensions run
on offline/scripted cores, and the live quality tier exercises only the agent's
reasoning, cost and latency — it never connects to a target. A future
*behavioural* eval that genuinely needs a live target belongs under `tests/e2e/`
against the frozen fixture (with the existing `_is_live` exemption), never against
the practice range.

## Commands

```sh
skuggi-eval --tier det --check            # offline gate: score deterministic dims vs baseline
make bench-fast                           # cheap quality signal: the `fast` suite, one model
make bench                                # full quality benchmark across the matrix (costs money)
skuggi-eval --tier all --update-baseline  # rewrite baseline.json (review the diff before commit)
skuggi-eval --tier quality --provider anthropic --model claude-haiku-4-5  # ad-hoc single model
```

`src/skuggi/templates/scope.example.json`, `src/skuggi/templates/tools.example.json`.
